## 概要

GitHub を人とエージェントの協働によってソフトウェアの仕事を完了する基盤として捉え、アプリ、連携、自動化、レビューを実演する。

## 内容の要点

- **考え方**：価値をトークン数や PR 数ではなく、問題を理解し、変更を検証し、届けて観察する「完了した仕事」で測る。計画・構築・検証・観察の各段階にコンテキスト、セキュリティ、ガバナンスを組み込む構想を示した。
- **アプリのデモ**：コーヒー店アプリのギフトカード実装を複数モデルと Copilot Fusion で比較。別の例では Git worktree を分けて店舗案内と営業中フィルターを並列作業し、プロジェクトでテンプレートと10ページの移行を複数 PR に分割した。Fusion の費用・品質比較は登壇者の特定デモであり、一般的な性能保証ではない。
- **連携と自動化**：Teams から GitHub を呼んで issue 作成や作業を依頼。Azure Monitor／SRE Agent による問題検出を起点に、再現・修正 PR・検証の automation を連結し、人がレビューしてマージする流れを示した。権限とクレジット上限を設定した PR 検証 automation も紹介。
- **レビューと制約**：Copilot Code Review の Max と Agent Merge の CI 失敗・競合への対応を紹介。Copilot のレビュー指摘を自動修正する選択肢は社内テスト中と明示した。Azure DevOps は PR 連携をデモした一方、質疑では Bitbucket の PR 連携はないと説明。証拠の整理は課題で、PR への artifacts 対応は今後の予定。
