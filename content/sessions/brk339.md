## 概要

利用者の端末上で動くローカルエージェントについて、アクセス先、実際の行動、管理上の可視性を検討します。

## セッションの内容

経理担当者がローカルエージェントを使って四半期決算を進める例を、IT 管理者、ID 管理者、SOC の三つの視点で追います。エージェントとユーザーの活動を区別し、必要なアクセスだけを許可することが中心です。

### 発見と端末での境界

Defender for Endpoint が対応するエージェントの実行を検出し、Entra Agent ID と Agent 365 のレジストリに結び付けます。デモでは利用者、端末、MCP サーバーとリスクを確認しました。Intune のポリシーで Microsoft Execution Container による実行を指定し、作業領域の読み書き、財務のネットワークドライブの読み取り、ローカルに同期された OneDrive ファイルへのアクセス禁止を設定しています。

### 動的な権限と SOC の調査

Dynamic permissions を用いて、Snowflake の作業に必要な読み取り権限を時間限定で与えます。ユーザー自身に権限のないデータへの要求は拒否されました。Defender と Purview の検出によってエージェントのリスクが上がると、管理者が設定したルールで一部の操作やアクセスを制限し、本人のアクセスは維持します。

SOC は Defender XDR のケースでエージェント、端末、ユーザーを関連付け、実際の露出を調査したうえで、リスクの解除やエージェントのブロックなど対応を選びます。発表時点では Intune のコンテナー管理、Dynamic permissions、Dynamic controls は限定プレビュー、ローカルエージェント向け Defender 実行時保護は一般提供と説明されました。
