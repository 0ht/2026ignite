## 概要

Microsoft Defender を使って AI 実行環境に Zero Trust を適用し、プロンプトインジェクションやツール・ID の悪用に備えます。

## セッションの内容

Zero Trust の「明示的な検証」「最小権限」「侵害を前提とした対応」を、エージェントとそのツール、データ、実行環境へ適用します。エージェントが読む文書やツールの応答には指示が混入し得るため、事前の設定確認と実行時の検出を組み合わせます。

### インベントリとリスク評価

Agent 365 のレジストリと Defender で、管理対象、サードパーティ製、ローカル、未承認のエージェントを把握するデモを紹介しました。エージェントから MCP サーバー、機密情報、権限などへの関係を調べ、過剰なツール権限や設定のずれを修復候補として提示します。

サードパーティ製エージェントの可視性は、そのプラットフォームが公開する情報や連携方法に依存します。デモでは実行時リスクや Entra Agent ID が取得できない場合も説明しました。

### 実行時の攻撃を止めて調べる

調達業務のデモでは、仕入先が提出した PDF の隠れた指示によって、エージェントの推奨結果が変わる例を示しました。Defender の保護を有効にした後は、対応するツール実行時に要求をブロックし、XDR のアラートから証拠を調査しています。

導入手順として、ライセンスと端末のオンボードを確認し、インベントリと修復候補を見たうえで、実行時ポリシーをまずアラートモードで評価し、その後ブロックへ進む流れを勧めています。
