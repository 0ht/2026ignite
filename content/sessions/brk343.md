## 概要

Entra の認証、条件付きアクセス、エージェント ID、動的な権限管理とネットワーク保護の方向性を紹介します。

## セッションの内容

### 人の ID 基盤を強くする

パスキーと Verified ID を組み合わせ、採用、復旧、機微なリソースへのアクセスなどで本人確認を求める方法を紹介しました。デモでは Teams 会議の参加前に本人確認を行っています。

Conditional Access policy plans は共通条件をまとめて複数のルールに適用します。PIM のデモでは、理由を添えて VM アクセスを有効化し、Bastion 経由の接続とセッション記録を確認しました。複数テナントの設定管理、設定のずれの検出、バックアップと復旧の拡張も取り上げています。

### エージェントの ID、権限、ネットワーク

Microsoft 以外のクラウドやローカルのエージェントを発見し、ID と管理対象に結び付けます。ライフサイクルワークフローではスポンサーの確認や非アクティブな ID の整理を自動化します。Dynamic permissions はタスクに応じた時間限定の権限を与え、Dynamic agent risk と Conditional Access はリスクに応じて操作を制御します。

Global Secure Access の MCP ポリシーのデモでは、エージェントごとに接続先や許可する操作を設定しました。Microsoft Graph の MCP サーバーを使って SAML SSO を構成するデモでは、テナントを変更する前に人が要求を確認します。Entra ポータルに Perception を統合する画面は将来構想として紹介されました。
