## 概要

Agent 365 と Entra でエージェントに ID を付与し、権限のライフサイクルやリスクに応じた修復を管理する例を示します。

## セッションの内容

### ID とアクセスのライフサイクル

エージェントに ID と責任者を割り当て、異動や退職時にはスポンサーの変更を通知し、管理者へ引き継ぐワークフローを紹介しました。非アクティブ、所有者不在、用途が確認されていない ID は、通知期間を設けたうえで無効化や削除を行います。

アクセスパッケージで承認と期限を設けるほか、Dynamic permissions ではタスクの目的に応じて最小限の権限を短時間付与します。Snowflake のデモでは、ユーザーが許可されていないデータをエージェントが要求しても拒否されました。既存の過剰な権限を検出し、管理者のポリシーに基づいて修復する例も示しています。Dynamic permissions は発表時点で限定プレビューです。

### NVIDIA の実装例

NVIDIA は、個人の代理エージェントと複数人が利用するエージェントを区別し、それぞれのアクセス範囲を管理する例を紹介しました。デモではメールや予定表、SharePoint、GitHub にアクセスし、エージェント自身の ID で操作を監査します。

実装例では実行環境に利用可能な長期認証情報を置かず、ワークロード ID、認証情報ブローカー、送信プロキシを組み合わせます。エージェントのアクセスを利用者と独立して取り消すことを目指した顧客側の設計例です。
