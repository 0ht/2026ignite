## 概要

Microsoft Fabric の Spark ワークロードについて、容量、並列性、セキュリティ、チューニングとコストを整理します。

## セッションの内容

### 構成と運用

Spark の本番運用を、構成、チューニング、監視、テスト・デプロイの四段階で説明しました。クラスタのサイズは CPU だけでなく入力元のスループット、メモリ、同時実行数を含むボトルネックに合わせます。固定容量と Spark の Autoscale Billing をワークロードの変動に応じて選択し、小規模処理は Python Notebook の利用も検討します。

High Concurrency Mode は条件の合う複数セッションで Spark を共有し、起動時間やコストを抑えます。既定は 5、最大 50 セッションと説明しました。ネットワーク分離、プライベートエンドポイント、行・列レベルの権限制御、プライベートなライブラリ配布も本番構成の検討対象です。

### ボトルネックの特定

Runtime 2.0 と Native Execution Engine の活用を推奨し、ネイティブ実行では顧客の事例で 2〜4 倍の性能向上があったと紹介しました。効果は処理内容によって異なります。性能改善では先に目標を定め、同じ入力・コード・計算資源で繰り返し測定し、結果の正しさ、実行時間と CU 時間を比較します。

Spark History Server でデータの偏り、遅いタスク、ディスクへの spill を調べ、実行計画から不要な shuffle を探します。大きな表と小さな参照表の結合では、小さい側の broadcast により大きな側の再分配を減らす例を示しました。

### 変更を安全に検証

PR ごとの単体テスト、定期的な負荷テスト、本番に近い統合テストを組み合わせます。テスト環境で Early Access リリースチャネルや自動更新プロファイルを試し、変更の影響を本番への展開前に確認する運用を紹介しました。
