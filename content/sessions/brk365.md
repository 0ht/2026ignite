## 概要

Cosmos DB 上の複数エージェントを Fabric で観測し、品質、遅延、費用の分析から改善ループへつなげます。

## セッションの内容

### 旅行プランナーの構成

Python と LangGraph を使う Cosmos Voyager では、監督エージェントが場所検索と旅程作成の専門エージェントを呼び出します。Cosmos DB に施設情報とベクトル、会話、実行状態、利用者の長期メモリを保存し、ベクトル検索と全文検索を組み合わせます。デモでは、保存済みのベジタリアンという好みを明示的に再入力せず、飲食店の提案に反映しました。

### 分析から設定変更まで

Cosmos DB のデータを Fabric にミラーして Spark Notebook で実行ログを分析し、LLM が改善案を生成します。結果を Spark コネクタで Cosmos DB に戻し、管理画面で提案を確認して適用する流れです。監督エージェントは各ターンの前にバージョン管理されたポリシーを読み、質問の複雑さに応じてモデルを選びます。デモでは小さいモデルへの振り分けと古いメモリの整理を改善候補に挙げました。

### Kinectify の本番事例

ゲーム業界向けの AML プラットフォーム Kinectify は、約 20 の専門・監視エージェントで顧客の追加調査を行うシステムを紹介しました。レビューの停止や別人の情報を誤って関連付ける問題に対し、各 LLM 呼び出しや外部サービス、Application Insights の情報を記録し、レビュー単位で追跡します。

Fabric のデータエージェントがモデルやプロンプトの改善を提案し、現時点ではデータサイエンティストが採否を判断します。自律的な低リスク変更は将来の構想です。発表者は、完全な観測、レビュー単位の相関、テレメトリ障害が業務処理を止めない設計を教訓に挙げました。
