## 概要

Azure SQL Hyperscale のスケール、可用性、ベクトル検索を活用し、重要業務向け AI アプリを構築する方法を紹介します。

## セッションの内容

### 小さく始めて需要に合わせて拡張

Hyperscale は SQL Server エンジンをクラウド向けに再構成し、発表時点で 10 GB のストレージと 0.5 vCore から始め、最大 128 TB・192 vCore まで拡張できると説明しました。コンピュートとストレージを分け、最大 30 の名前付きレプリカで読み取りを分散できます。ライセンス料金を別途加算しない価格モデルも強調しています。

サーバーレスは使用量に応じてコンピュートを拡縮し、設定した遅延後に一時停止できます。弾力的プールでは複数データベースが共有コンピュートを使い、個々の上限を設定してテナント間のリソース偏在を防ぎます。デモでは医療予約システムが日中の利用に応じて伸縮する様子と、複数クリニックの DB をプールにまとめる例を示しました。

### クロスデータベース処理と可用性

プール内のデータベース間で参照・更新するクロスデータベースクエリを紹介しました。デモではクリニック間の予約枠を検索するビューと、別 DB への更新・挿入を実演しています。この機能は発表時点で限定プレビューとして案内されました。

ストレージとコンピュートの分離、ゾーン対応の高可用性レプリカ、障害時の自動フェールオーバー、読み取り用の名前付きレプリカを図解しました。名前付きレプリカはデータを複製せず、独立したコンピュートでレポートやベクトル検索を実行し、プライマリへの影響を抑えます。

### AI 検索とエージェント

JSON、正規表現、あいまい一致、ベクトル型・索引、フルテキスト検索、変更イベントストリーミングなど、SQL エンジンの AI 開発向け機能を紹介しました。デモでは医療研究記事をベクトルとキーワードのハイブリッド検索で調べ、名前付きレプリカ上で約 10 億行規模の検索を実演しました。数値は発表時点のデモ環境に基づくもので、一般的な性能保証ではありません。

Foundry エージェントと SQL MCP サーバーを接続し、複数の検索を実行して調査結果と次の提案をまとめる例も示しました。顧客 CDW は GitHub Copilot で開発したエンタープライズ・アーキテクチャ管理アプリに Hyperscale を使い、リレーショナルデータ、ベクトル、SQL Graph を組み合わせたポートフォリオ検索を構築したと説明しています。
