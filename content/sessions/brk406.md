## 概要

Windows と Cloud PC 上での AI 利用について、エージェントの保護、端末とクラウドの連携、企業での展開を扱います。

## セッションの内容

このセッションが掲げる「hybrid intelligence」は、Windows PC と Windows 365 Cloud PC を、ユーザーやエージェントが使うローカルの文脈・アプリ・データの基盤と捉え、端末上のモデルと Azure の Frontier モデルをタスクごとに使い分ける考え方です。冒頭では、まずエージェントの信頼性を確保する仕組みとして、個別の Microsoft Entra Agent ID、Windows 上で実行範囲を隔離する Microsoft Execution Containers（MXC）、Intune と Agent 365 を通じた管理を紹介しました。デモでは、Defender がプロンプトインジェクションを検知し、未承認エージェントを見つけた端末を準拠ポリシーで制限する流れも示されました。

続いて、Copilot が許可を得てローカルのファイルやアプリの文脈を使い、Windows の設定変更などの操作を行う構想を説明。簡単な処理やデータ確認は端末上のモデルに回し、複雑な推論は Azure 側に送る「インテリジェントルーティング」を GitHub Copilot Fusion の例で紹介しました。デモでは、コードの複雑な変更にクラウドモデルを使う一方、ログや設定ファイルのローカル確認・レビューには端末上のモデルを使う流れでした。MCP、Windows ML、MXC を使えば、企業が構築するエージェントにもローカルの文脈やアクションを許可制・境界付きで提供する狙いです。

人と並行して動くエージェントだけでなく、人が離席中も業務アプリを操作する自律型エージェントには、Windows 365 for Agents が専用の Cloud PC を提供する仕組みとして紹介されました。登壇者によると、Copilot Studio の computer-use tool として利用可能で、永続 Cloud PC はプレビュー、Foundry 対応は近日予定でした。デモでは、担当者が記録した手順をもとにエージェントが既存の請求システムで割引を修正し、定期的に処理を繰り返す例を示し、担当者が作業を監視・誘導・引き継げることを強調。Microsoft Business Operations の受注処理では、処理時間が60%短縮したとも述べられました。最後の顧客事例では、Flagstar Bank が Surface 端末上の小型言語モデルによる Branch IQ を使い、社内規程や手順を顧客対応中にも素早く参照できるようにしたと説明。ローカル実行を選んだ理由として、規制対応に必要なガバナンス、追跡可能性、監査性を挙げました。

終盤では、Copilot+ PC、Cloud PC、常時稼働エージェント用端末、開発者向け端末、データセンターの Windows Server、Azure を連続した AI インフラとして計画する提案もありました。製品機能や性能値は登壇中の説明・デモに基づくもので、独立検証された結果を示すものではありません。
