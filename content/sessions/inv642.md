## 概要

Agent 365 と Perception を通じて、AI の利用状況、エージェントのリスク、事業価値、費用を可視化する方法を紹介します。

## セッションの内容

### Agent 365：可視化から運用・投資判断へ

- **共通の台帳とアクション**：Microsoft 製だけでなく他社プラットフォームやツールも登録・把握し、Action Center にセキュリティ、権限、コストなどの対応事項を集約する。デモでは Databricks のワークスペースを接続し、MCP サーバーの操作を制御したうえで、所有者不在のエージェントを前任者の上司に自動で再割り当てした。
- **計画・制御・最適化**：利用者やモデル、予算を計画し、接続先や消費に制約を設け、実際の利用状況を見てモデル構成などを最適化する。Philips は Cowork の利用者をニーズに応じた複数の区分に分け、利用拡大と費用管理を両立させる事例を紹介した。
- **事業側の分析**：Business Analytics のデモでは、サービス・モデル別の支出、利用目的、ユーザーや部署別の費用、モデル変更時の予測を確認した。業務価値は各社の作業時間・コストから算定する推定値であり、現金削減額ではない。低コストモデルへの切り替えは出力品質の評価と併せて判断する。
- **予算と連携**：Cowork の費用予測を基に支出ポリシーを設定し、部門に費用を配賦する例を示した。分析データは Fabric、Power BI、MCP 対応クライアントなどに接続でき、発表時点では Business Analytics などが Frontier Public Preview と説明された。

### Perception：防御とエージェントの統制

- **セキュリティの構成**：信号を関連付けたセキュリティコンテキストを基盤に、攻撃を模擬する赤、検知・調査を担う青、設定やリスクを改善する緑のエージェントを組み合わせる。脅威情報から検知を改善し、設定を修正して再検証するループが説明された。
- **SOC と脆弱性対応のデモ**：アラートのトリアージ、攻撃調査、検知ルール作成を Playbook で連携し、公開前に人が承認した。別の例では MDASH の48件の検出結果をペネトレーションテストで検証し、実証された3件に対する修正案を GitHub のプルリクエストとして提示した。テスト実行も人の承認を必要とする例だった。
- **エージェントの封じ込め**：Perception と Agent 365 は同じエージェント台帳を共有する。デモではユーザーとエージェントの ID を分け、タスクに必要な権限を動的に付与し、危険な指示や機密データへの要求を防御した後、上昇したリスクに基づいてエージェントのアクセスを制限した。
- **基盤の改善と提供状況**：管理者の認証強化や、脅威情報に基づく公開サーバーのリスク優先順位付けを実演した。IT が担当する対策は既存の役割権限を尊重し、承認後に進める。発表では Perception の「Defend with Agents」は一般提供、エージェントと基盤の保護に関する一部シナリオはプレビューと区別していた。
