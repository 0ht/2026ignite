## 概要

Azure と Windows をまたぐ AI インフラについて、推論、エージェントの隔離、機密コンピューティング、エッジ利用を紹介します。

## セッションの内容

### Azure の基盤と運用

- **エージェント向けの基盤**：Agent Grid はサンドボックスのネットワーク接続を制御し、Context Cache は推論コンテキストのキャッシュを Azure Storage に保存する。Azure Container Instances の Agent Sandboxes は microVM による隔離を提供し、登壇者は起動時間が0.5秒未満と説明した。
- **Foundry と AKS**：AKS AI Manager により Kubernetes 上で AI ワークロードや GPU を管理する構想を示した。工場のデモでは、既存の AKS クラスターを Foundry に接続してモデルを配置し、AKS Flex Node で工場内の GPU・カメラも組み合わせ、製造ラインの停止原因を調査した。診断時間はデモ上、2時間から4分になった。
- **Azure Catalyst**：ServiceNow のインベントリを取り込み、アプリケーションの依存関係と移行費用を分析する例を紹介。ランディングゾーンの要件に従い、Web・データ・ファイルをそれぞれ Azure のサービスへ割り当て、データベース管理者や開発者が既存ツールで作業しながら移行・検証する。
- **機密性と配置場所**：Confidential Computing はハードウェアに基づく実行環境で使用中のデータも保護する。機密 VM、AKS の機密コンテナー、データサービスの拡充を説明し、別のデモでは Azure Local をクラウドから切り離して Foundry Local のエージェントとローカル文書を利用した。

### Windows のセキュリティとハイブリッド AI

- **端末の基礎防御**：Windows Endpoint Security Platform はセキュリティ製品の重要な保護機能をカーネルからユーザーモードに移して耐障害性を高める。Windows Baseline Protection は Secure Boot などの状態をまとめて確認でき、Administrative Protection は必要な操作に限って管理者権限を昇格する。
- **エージェントの実行境界**：Microsoft Execution Containers（MXE）でファイル・ネットワークへのアクセスを制御し、ユーザーとは別のエージェント ID を使う。デモでは通常の文書作業と、疑わしいマルウェアの検査に異なる隔離レベルを適用した。Windows 365 for Agents でエージェント専用のクラウド PC を使う選択肢も紹介された。
- **ローカルとクラウドの使い分け**：Windows Hybrid Intelligence のデモでは、利用者の許可を得て音声設定を診断し、ローカルファイルを OneDrive に整理した。Copilot Fusion は対応 PC 上のローカルモデルも活用し、必要に応じてクラウドモデルを使うプレビューとして紹介された。
- **管理とインフラの選択**：Windows Autopatch、Intune と宣言的管理による更新・設定管理に加え、Windows 365 の Direct Stream と Windows Server 2028 のパブリックプレビューを紹介した。PwC の対談では、職種に必要な作業を起点に端末・ソフトウェア・クラウドの配置を設計する重要性が強調された。
