# BRK236: Agents in Copilot: help every user get more done

Agent Builder などによるエージェントの作成方法と、利用者への定着、信頼、ガバナンスの考え方を整理します。

確認日 2026-11-24

## 概要

組織固有の知識や業務手順をエージェントに組み込み、Copilot を通じて共有・活用する方法を紹介します。Agent Builder、Copilot Studio、Foundry の使い分けに加え、週次報告を作る実例と、共有・承認・利用状況の管理を説明しています。

## 作成方法の使い分け

- **Agent Builder**：業務担当者が Copilot 内で自然言語を使い、軽量なエージェントを作成します。チームの新入社員向けに、選択した SharePoint や文書を参照する案内役が例です。登壇者は、権威ある情報に基づく案内と、定型成果物の作成を代表的な用途として挙げました。
- **Copilot Studio**：業務プロセス向けにエージェント、ワークフロー、アプリを組み合わせます。発表されたエージェントのアカウントとメモリ、外部システムへのコネクタ、MCP やエージェント間通信にも言及しています。
- **Foundry と GitHub**：開発者がコードやモデルを選び、高度なカスタマイズを要するエージェントを構築します。Foundry の管理された実行環境、サンドボックス、トレースや評価が紹介されました。Copilot Studio のエージェントを MCP として公開するなど、各経路を組み合わせることもできます。

## デモ：週次報告エージェント

Ned Friend は、自身のチームの「Shiproom Reporter」を例に、Azure DevOps の作業項目、メール、過去の報告書を参照して、リスクや意思決定・次のアクションを含む Word の週次報告を作成しました。新規作成では過去の手書き報告書と要件をプロンプトで渡し、Agent Builder が指示とスキルを作成。期限比較用のスクリプトも生成したと説明しています。

さらに、別の仕様レビュー用エージェントをリンクし、参照する Teams 会議を対象の定例会に絞り、DevOps と Exchange のコネクタを選択し、不要な Web 検索をオフにしました。Outlook アクションはメールや会議依頼の**下書き**を作るもので、送信は利用者が行います。プレビュー後のエージェントは最初は非公開で、共同編集者への共有時には必要な参照文書へのアクセスも確認します。

## 利用定着と管理

作者はセッション数、日次アクティブユーザー、知識ソースの利用状況を確認し、組織全体への公開は管理者に申請できます。管理者側では、コネクタを設定し、組織のエージェントを一覧・ブロック・配布できるほか、組織全体への直接共有を制限して承認経路を設ける例が示されました。

Agent 365、Entra、Purview、Defender を用いたアクセス管理、リスク把握、可観測性にも触れています。Agent 365 の費用管理については、Copilot Credit Estimator による予算策定と、ユーザー別・エージェント別のコスト確認が説明されました。

## 発表時点の提供状況・制約

登壇者は Agent Builder について Copilot Chat に含まれ、Copilot ライセンスがあれば利用開始できると説明しました。スキル追加、Fabric データへのグラウンディング、共同編集などもデモで紹介。一方、**完全なプラグインの作成、イベントを契機とする実行、バージョン履歴**は今後の予定として語られています。これらはセッション時点の説明であり、現在の提供状況や利用条件を保証するものではありません。
