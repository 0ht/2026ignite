# BRK237: Plugins for Copilot: build once, govern once, use everywhere

ツール、スキル、エージェントをプラグインとしてまとめ、作成から公開、評価、企業内管理まで共通化する方法を示します。

## 概要

Copilot のプラグインにツール、スキル、エージェントをまとめ、作成・評価・配布・改善する流れを紹介します。Adobe の写真編集と、架空の製品ローンチ準備確認を例に、Work IQ Developer Tools と組織内の承認手順を実演しました。

## プラグインの構成と配布

プラグインは Microsoft 365 アプリのパッケージで、マニフェストに MCP サーバーなどのコネクタ、スキル、Copilot エージェントをまとめられます。利用者は個々の部品を別々に探さず一つのパッケージを追加でき、Copilot の複数の利用画面で使えます。管理者は Microsoft 365 管理センターなどから配布や利用を管理します。

冒頭の Adobe の例では、OneDrive に保存した出張写真をパートナーのスキルと MCP サーバーを介して Adobe のクラウドで加工し、共有用の Firefly ボードを作る流れを紹介しました。

## デモ：ローンチ準備を確認するプラグイン

登壇者は、架空の Caldova 社のカスタマーサービスポータルについて、Cowork に「ローンチできるか」と尋ねました。プラグインは接続先のサーバーから情報を取得し、予定日が想定と異なり、承認もまだそろっていないと回答しました。

続いて GitHub Copilot アプリと Work IQ Developer Tools（WIQD）で同じ仕組みを作成。過去の Teams 会議の記録やチャットから要件を整理し、スキル、MCP 接続、エージェントを含むパッケージを生成して、Cowork または Chat で試します。生成物は人が確認でき、MCP のほか Power Platform コネクタや OpenAPI で記述された API も接続方法の例として挙げられました。

評価では、正しいツールの呼び出しやスキルの実行に加え、回答が「ローンチの承認」ではなく「準備状況の評価」になることを検証します。デモの改善後の結果は **12 件中 10 件成功、2 件失敗**で、完全な合格ではない状態で同僚とのテストに進む例です。利用者の評価・コメントを取り込み、評価ケースやスキルの改善につなげる流れも説明しました。

## 公開とガバナンス

GitHub のプルリクエストをレビューしてマージすると、パイプラインが検証と組織カタログへの公開申請を行い、管理者が MCP の接続先やツールを確認して承認する例が示されました。ソフトウェア提供者向けには、Partner Center を通じた公開フローも紹介されています。開発ツールには対話式の作成支援に加え、ソース管理や CI/CD に組み込む CLI があると説明されました。

## 発表時点の提供状況・制約

WIQD は Work IQ プラグインとして紹介され、既存の Agent Builder エージェントや他のエージェントプラグインを開発ツールへ取り込む機能、ツール呼び出し・スキル実行の評価が発表されました。一方、**Agent Plugin Standard 形式のプラグインを変換せずレジストリで直接使う対応**、Cowork を対象とする評価、より詳細なプラグインのフィードバックや Partner Center 管理機能は今後の予定として説明されています。開発ツールへの取り込みと、レジストリでのネイティブ対応は別の話です。提供状況は発表時点の説明であり、現在の利用条件を保証するものではありません。
