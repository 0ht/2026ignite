## 概要

異なるフレームワークや環境のエージェントに共通の管理を適用し、Foundry の企業向け統制につなぐ考え方を説明します。

## 内容の要約

冒頭では、エージェントの普及速度に対して安全・統制の準備が追いついていないという課題を示し、エージェントの各実行段階に「ポリシーを定義する・実行時に強制する・評価する・証跡を残す」という統制サイクルを提示します。後半では、複数のフレームワークやクラウドにエージェントを分散して運用する架空の銀行「Caldova Bank」を例に、組織共通とエージェント固有のルールを一元的に適用する方法を説明します。

中核となる発表は Agent Controls です。スライドでは Public Preview とされ、オープンソースの Agent Hooks が実行時の介入点を標準化し、Agent Control Specification (ACS) がランタイムとポリシーエンジン間の要求・判定の契約を担う構成を紹介します。ポリシーエンジンは決定的なルール、安全性分類器、LLM judge などを使い、続行・拒否・変換・人へのエスカレーションを返します。説明では、Azure AI Content Safety リソースを基盤に、複数のフレームワークやクラウドのエージェントから共通 API を利用できる設計が示されます。

デモでは、銀行の顧客情報を回答に出さない、1万ドルを超える送金・返金を人の承認に回す、経済的困窮を訴える顧客への追加販売を止めて担当者につなぐ、といった要件を例示します。金額条件はツール呼び出し前の決定的ルールで止め、困窮の判定には LLM judge を使う設計です。人間の言葉で書かれた要件をポリシーへ落とし込み、共通の基準と個別エージェントのルールを重ねられる点も実演されます。

また、HPE の登壇者は、複数クラウド・プライベート環境・SaaS にまたがるエージェント群のガバナンス課題を紹介し、標準化されたフック、再利用可能なポリシー、責任主体と権限の明確化、フェイルクローズ、監査証跡の必要性を説明します。終盤では、オープンソースの ASSERT を使い、要件からテストシナリオとスコアカードを作成する流れを示します。銀行の「困窮時に追加の金融商品を勧めない」評価例では、統制適用前のポリシー違反率 37.5% が適用後 0% になったというデモ結果を提示し、OpenTelemetry のトレースで適用ポリシー、バージョン、判断、実行結果を後から確認する方法で締めくくります。
