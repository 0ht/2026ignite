## 概要

Foundry を中心に ID、ポリシー、AI Gateway、コスト、観測性をまとめ、Agent 365 と連携して AI を運用する方法を整理します。

## 内容の要約

セッションは、エージェントが1体の試作から多数の部門・所有者にまたがる「フリート」へ増えると、個別の連絡や表計算では統制できなくなるという問題提起から始まります。以降、架空の Mesa Verde Bank の顧客対応エージェントと従業員向け面談準備エージェントを使い、エージェントごとに繰り返し問われる「何にアクセスできるか」「いくらかかるか」「安全か」「誰がルールを定めるか」を、構築から組織運用まで一貫して扱います。

前半のデモでは、Azure Policy で許可するモデル発行元を OpenAI に限定し、Foundry のツールも file search のみに制限します。許可外の Kimi モデルや web search は作成・保存時に拒否されます。コードで作る hosted agent については、実行時ツール制御で MCP エンドポイントを許可リスト化し、ネットワーク egress も承認済みホスト以外を遮断します。承認された MCP 呼び出しは通し、禁止された呼び出しはランタイムのトレースで拒否理由まで確認します。エージェントごとの Microsoft Entra ID と agent blueprint により、ユーザー権限に基づくアクセスと個別の管理可能性を説明します。

本番運用のデモでは、Foundry のコスト画面でエージェントやプロジェクト別の支出を確認し、月次などの予算上限と通知・利用停止のしきい値を設定します。また AI Gateway を中央のモデル／ツール通信経路として接続し、Foundry プロジェクトに公開するモデルを選ぶ流れを示します。安全対策では Guardrails を使い、個人情報の検出に加え、1万ドル以上の送金を人の承認に回す決定的ルールと、経済的困窮の兆候を LLM judge で評価して人の担当者へ引き継ぐカスタムルールを構成します。Azure Policy で適用範囲をサブスクリプションへ広げ、Foundry のコンプライアンス画面でポリシー違反や要対応のエージェントを確認する流れも紹介されます。

終盤では、ポリシー、資産、脅威・データ保護の情報を見渡す Foundry のコンプライアンス／運用画面、エージェントごとのエラー・遅延・トークン利用、評価の経時変化とトレースの確認を説明します。Agent 365 は Foundry 外のエージェントも含むテナント横断管理の位置づけで、Agent 365 で定めた安全ポリシーを Azure Policy 経由で Foundry エージェントに適用する連携が示されます。

## 提供状況

スライドは Agent Controls を「early access」とし、Foundry と Agent 365 での利用は申込制の早期アクセスとして案内しています。Agent 365 側のポリシー機能は登壇者が「coming very soon」と説明し、カスタムガードレールの拡張も今後の予定として述べています。コスト、Gateway、Guardrails、コンプライアンスなどの画面はデモで紹介されていますが、各機能の提供段階は一律ではなく、このセッション資料だけでは全機能の一般提供を確認できません。
