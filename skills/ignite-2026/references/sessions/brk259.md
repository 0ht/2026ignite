## 概要

Copilot Studio の Copilot SDK ベースのハーネスを取り上げ、スキル、フック、複数エージェント、ワークフローの関係を説明します。

## 内容の要約

Alice Appleton は、Copilot Studio の新しいエージェント実行基盤を Microsoft Copilot SDK ベースにした理由を解説しました。従来のチャット型ハーネスが単発応答向けに段階的なプロンプトを組むのに対し、推論型ハーネスではエージェントが計画・実行・結果確認・適応を繰り返し、長いタスクを完了させます。Copilot SDK がモデル／ツールのルーティング、コンテキストとメモリ、制限と障害回復、テレメトリと評価を担い、Azure コンテナー内の CLI とファイルシステムを使う構成として説明されました。

### 設計と評価

- この基盤は Microsoft Copilot SDK のエージェント実行ループに、Copilot Studio の業務プロセス向け制御を組み合わせます。発表では、標準ハーネスとの社内オフライン評価（約500のテストケース）で、知識利用 +20.4ポイント、コード分析 +47.5ポイント、ファイル分析 +28.2ポイント、複数ツール利用 +11.9ポイントの品質向上と、入力トークン45%減を報告しました。これは Microsoft の評価結果であり、独立した第三者ベンチマークではありません。
- モデルは OpenAI、Anthropic、Mistral、SpaceXAI の選択肢を用意し、管理者ポリシーを尊重しながら、コストと品質に応じた自動選択も提供する方針です。スライドでは Copilot Studio 自身も複数のエージェントを使って開発する事例を紹介しています。

### デモで示された機能

- **動的タスクエージェント**：サプライヤー提案の評価で、メインエージェントが提案ごとの子エージェントを動的に起動し、並列かつ独立に採点・懸念点を調査してから結果を統合しました。続いて別モデルのエージェントに結論を批評させる例を示し、個別エージェントを事前に作成・公開・管理せず、タスクに応じて使い分ける方式を説明しました。
- **フック**：エージェントのライフサイクルイベントに紐づく決定的な処理です。セッション開始、ユーザープロンプト、ツール実行前後、ツール失敗、エラーをイベントとして扱い、ツール呼び出しを毎回記録したり、ポリシーを適用したりできます。購買デモでは利用者の予算情報をセッション開始時に読み込み、購入前フックが上限超過の発注を拒否し、数量を下げた再試行は許可しました。ツール実行後に結果を編集・秘匿する用途も説明されています。
- **変数**：利用者の部署・権限などを変数としてエージェントへ渡し、利用可能なツールや知識を実行時に絞る設計を紹介しました。これにより、モデルの判断に委ねる範囲と固定する入力を分けます。
- **複数エージェント連携**：A2A、Microsoft Foundry、Microsoft 365 Agents SDK で作られたエージェントを接続する方法、および Copilot Studio エージェントを MCP または A2A のサーバーとして公開する方法を示しました。

### 提供状況・時期

- スライドではモデル選択、自動選択、既存の複数エージェント接続、フック、ユーザーメモリを「利用可能」としています。動的タスクエージェントとフックは「プレビュー、12月に一般提供を目標」と記載されています。
- MCP/A2A サーバー公開は「プレビュー環境で利用可能、一般提供は2027年1～3月期を目標」とされています。フックの「タスクエージェント完了／ターン完了」イベントと Python コード実行は2027年1月予定、変数管理の改善・セッション開始時の初期化・条件に基づくツール／知識の可用性、過去セッション検索や継続的自律セッションは「近日予定」と説明されています。
- これらはセッション発表時の資料に記載された提供状況・目標時期であり、個々の機能のその後の公開状況を確認したものではありません。
