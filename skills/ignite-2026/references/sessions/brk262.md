## 概要

Copilot Studio と管理センターを通じ、エージェントのセキュリティ、利用状況、費用を組織規模で管理する方法を扱います。

## セッションの要点

### 機能に応じた多層ガバナンス

スライドでは、エージェントがデータやツールにアクセスし、利用者の代理で操作するようになるほど、追加の管理が必要になると説明しています。Copilot Studio を例に、各管理者の役割を次のように分けています。

- **Power Platform 管理者**：環境の配置、コネクタ・共有の方針、作成から公開までの管理。
- **ID・アクセス管理者**：Microsoft Entra でエージェントの ID とリソースへのアクセスを管理。
- **コンプライアンス・セキュリティ管理者**：Purview で情報を保護し、Defender で脅威を検出・対応。
- **AI 管理者**：Microsoft 365 管理センターと Agent 365 を通じてエージェント全体を把握し、利用状況や費用を確認。

作成者がどこで何を作れるか、誰が公開・利用できるか、エージェントが何にアクセスできるかを、それぞれ別の管理課題として整理しています。

### 費用の計画・制御・最適化

費用管理を、予算の見積もり、制限やアラートの設定、利用状況に基づく最適化の3段階に分けています。作成者向けにはプレビューチャット、評価、エージェントの監視画面でクレジット消費を確認する機能が示されました。

Power Platform 管理センターでは環境単位の方針、クレジット割り当て、在庫や利用状況の確認を扱います。ユーザー・エージェント・機能・日ごとの利用を扱う Reporting API は、スライド上で**パブリックプレビュー**と記載されています。

Microsoft 365 管理センターの方向性として、重要なエージェントや環境に予算を割り当てる方式と、作成者個人に利用枠を割り当てる方式を紹介しています。ユーザー・グループ単位の方針は今後の予定として示されているため、利用可能な範囲は導入時に確認が必要です。

デモでは Power Platform 管理用プラグインと API を使って環境の一覧や独自ダッシュボードを作り、Microsoft 365 管理センターでアクセス、接続先、リスク、支出を確認しました。Lumen は、個人開発環境で試行した成果を利用範囲に応じて昇格させ、重要な業務には別の予算や承認を設ける運用を紹介しました。

### 導入の進め方

スライドは、管理ロールの割り当て、既存環境のクレジット・課金・所有者の確認、必要な方針の選択、1環境での試行、段階的な展開を推奨しています。環境やエージェントを一括で管理する場合も、制限とアラートを実運用に合わせて検証することが重要です。
