## 概要

チームのスキルや指示を GitHub Copilot に組み込み、ツール連携、テスト、レビューを伴う開発フローを整える方法を扱います。

## セッションの内容

VS Code チームの登壇者が、個人のエージェント活用をチームで再利用できるワークフローに育てる方法を、スキル、プラグイン、評価、管理設定のデモで紹介します。

### スキルの作成と評価

`AGENTS.md` にはリポジトリの構造や開発上の基本情報を簡潔に置き、特定の作業手順は必要に応じて読み込むスキルに分けます。デモでは望ましいプルリクエストの説明と避けたい例を基に、エージェントにスキルの下書きを作らせました。

共有前には、呼び出すべきケースと呼び出すべきでないケースを含め、スキルの有無による結果を評価します。品質だけでなくトークン使用量も比較し、モデルやスキルの変更による影響を継続的に確認する例が示されました。

### 配布と運用

スキルや MCP をプラグインとしてまとめ、マーケットプレースで発見・配布・更新します。企業の管理設定で提供元や必須のプラグインを制御し、チームやリポジトリ単位では既定で有効にする方法も紹介しました。最初はチームの一、二の課題に絞り、評価とフィードバックを重ねて広げることを勧めています。

### 自動化と Canvas

デモでは、プルリクエストをビルドして操作動画を記録する自動化と、夜間に製品を操作して問題を報告する処理を紹介しました。Canvas はエージェントと双方向にやり取りできる画面で、発見した問題の確認や起票などを支援します。利用状況や評価結果を基に、共有するスキルを改善します。
