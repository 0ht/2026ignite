## 概要

GitHub Copilot アプリで複数エージェントへ並列に作業を委任し、変更の検証、PR、Agent merge、自動化につなげます。

## セッションの要点

### 複数の作業を調整する

GitHub Copilot アプリでは、issue やプルリクエストからセッションを開始し、ローカルまたはクラウドのエージェントに作業を任せる例が示されました。ローカルの並列セッションは作業面を分離して進めます。複数リポジトリにまたがる仕事では、親の会話から子セッションを作成し、進捗や質問を集約する使い方を紹介しています。

登壇者は、各セッションを常時監視する代わりに、プロジェクトのコーディネーターで成果と判断が必要な事項を確認する方法を説明しました。必要な場合は個別セッションを開き、詳細を確認して方向を修正できます。

### 画面操作と検証

デモではブラウザーの対象要素を選んで会話にコンテキストを渡し、画面の変更を指示しました。拡張可能なキャンバスを使い、issue のトリアージから複数の作業セッションを起動する例も示されました。

変更の検証では、ブラウザーを操作してスクリーンショットや動画を残し、成果を確認する方法を紹介しています。デスクトップやモバイルの画面操作にも触れ、エージェントが作った画面へ実際に移動できるかを確認する重要性を説明しました。

### プルリクエストを着地させる

Agent merge は、プルリクエストのレビュー対応、CI の失敗、マージ競合を扱う機能として紹介されました。マージまで任せるか、対応だけ行って未マージで残すかは設定で選びます。GitHub チームの事例では、PR 上で成果、UI の変化、性能、リスクを確認し、機能フラグを使って段階的に公開すると説明しています。

### 自動化と組織設定

定期実行やイベントを契機とする自動化として、issue の分類、クラッシュの調査、セキュリティレビュー、日次の情報整理を紹介しました。CI の改善事例では、テストを削除しないという制約を与え、改善を繰り返したと説明しています。

スキル、プラグイン、MCP サーバー、コネクタで外部情報を取り込み、組織の管理設定で既定モデルや利用できる拡張機能を制御する方法も紹介されました。クラウド実行時にも必要な接続先を使えるようにすることが、作業をローカルから移す際のポイントです。
