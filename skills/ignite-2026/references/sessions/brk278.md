# BRK278: Inside Copilot code review: From context to approval

Copilot コードレビューがコンテキストとチームの規約を取り込み、複数のレビュー強度や評価を組み合わせる仕組みを説明します。

確認日 2026-11-24

## 概要

Copilot code review が変更差分だけでなく関連コードやチームの知識を使い、複数のレビューを統合して判定する仕組みと、その統制を説明します。

- **デモ:** OpenCost の PR で Balanced レビューがクエリの問題を検出し修正を提案。修正後の再レビューで問題が解消したことを確認し、承認推奨を出します。リンクされた Issue の受け入れ条件の未達や、依存更新と別変更を分けるスキルの違反を検出する例も紹介します。
- PR の説明・差分・関連 Issue に加え、リポジトリ内の指示やスキル、MCP 経由の外部情報を利用。過去のレビューからパターンを学ぶ Dreaming とクロスリポジトリのコンテキストは、発表時点ではパブリックプレビューです。
- 複数のレビューエージェントの結果を集約し、重複排除と重大度の整理を行います。Light／Balanced／Max と、リスクに応じて選択する Adaptive を説明し、Adaptive は当時パブリックプレビュー。Max は高重大度の問題を Balanced の約2倍発見したという登壇者側の測定です。
- 判定は変更推奨、要精査、承認推奨。実際の承認は既定では無効で、有効化するとブランチ保護の承認数に算入できます。組織・リポジトリやパスを限定し、低リスクから試すことを推奨。発表時はブランチ単位の設定には未対応です。
- AI によるシークレット検出は任意のパブリックプレビュー。Azure Repos 向け Copilot code review は GA と説明。クロスリポジトリ参照は当時、既定で公開リポジトリのみで、参照先指定は今後の予定でした。
- 評価は人手ラベル付き PR の適合率・再現率と実運用での指摘対応率を併用。指摘対応率は LLM 判定による推定であり、検出漏れや誤検知がない保証ではありません。
