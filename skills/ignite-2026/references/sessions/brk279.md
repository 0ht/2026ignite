# BRK279: Building a model for software development from the ground up

コーディング向け MAI モデルの設計、学習、品質・遅延・費用の評価と、製品利用からの改善を紹介します。

確認日 2026-11-24

## 概要

MAI Code 2 系を例に、コーディングモデルを実際のハーネスと一体で学習・評価し、オンライン実験から改善する過程を紹介します。

- 事前学習に続き SFT と強化学習で、推論、ツールを使う行動、ユーザー意図と不確実性への判断を訓練。Microsoft Kiota Python SDK の例では、値 0 を保持し None のみ省く修正をテストし、候補ごとの報酬で学習する流れを説明します。
- Copilot CLI／SDK や VS Code など実際の製品ハーネスを訓練・評価環境に取り込みます。難しい課題には推論を増やし、簡単な課題には不要なトークンを使わないよう、品質とコストを両立させる設計です。
- オフライン評価では公開・社内ベンチマークの合格率だけでなく、ハーネス、解の長さ、推論レベル、初回応答・生成速度、コストを見ると説明。フロントエンド制作例も紹介しました。
- 実利用では同等の利用者・配信条件を揃えた A/B テストで、モデル単体の比較とルーティング候補群の比較を区別。利用継続、生成コードの残存、トークン、遅延、エラーを併せて解釈します。ターン数増加は有用性にも追加の手戻りにもなり得ます。
- 発表当日に MAI Code 2 と Code 2 Flash を公開。前者は日常の企業開発向け、後者は小さな定型修正向けで、最先端の科学研究や非常に長期のタスク向けではないと明言。スライドの価格比較は**当時の50%割引**を含み、恒久価格ではありません。
- 複数モデル間で簡単な作業を小型モデルへ委譲する構想や Foundry でのカスタム調整は将来・進行中の話として説明しています。
