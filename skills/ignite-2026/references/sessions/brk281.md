# BRK281: Securing coding agents and their code

コーディングエージェントの権限、隔離実行、組織ポリシーと、生成されたコードの安全性を管理する方法を扱います。

## 概要

コーディングエージェントそのものの実行権限と、その生成コードの両方を、組織ポリシーと複数のセキュリティゲートで守る方法を紹介します。

- スライドは管理設定の**推奨ベースライン**として、権限回避を無効化し、本番操作や認証情報へのアクセスを拒否、パッケージ導入やネットワーク操作に承認を求める構成を示します。これは全組織に自動適用される既定値の主張ではありません。
- シークレットは用途・所有者・期限を決め、リポジトリ単位などで最小権限に限定。エージェントから見えるシークレットはモデルのコンテキストに露出し得る前提で扱います。Ruleset、必須 PR、レビュー、CodeQL のしきい値で人とエージェント双方の変更を制御します。
- クラウドとローカルの Copilot sandboxes は発表時 GA と説明。ローカルの隔離とネットワーク制限、クラウドの一時環境を使い分けます。**デモ:** Package Firewall による危険な npm パッケージの導入ブロックと、承認・検査が未完了の PR のマージ阻止を示します。
- 別の注文管理アプリでは coding agent に API 追加を依頼し、シークレットや変更を検査。ローカルの security review は SQL インジェクションと XSS を検出し、push protection はテスト用シークレットの送信を阻止。Agentic Autofix は修正 PR を作り既存テストを実行しますが、人による検証と承認は必要です。
- Copilot code review のシークレット検出は発表週に追加され、コードスキャン・品質チェックの同レビューへの追加や security review での追加スキャンは「近日」と説明。自動マージの安全な境界についてはまだ発展途上で、規制・コンプライアンス次第だと回答しています。
