## 概要

増加するセキュリティ backlog に対し、依存関係・自作コード・秘密情報を予防、優先順位付け、修正の順に管理する。

## 内容の要点

- **依存関係**：Package Firewall で既知のマルウェアや重大な脆弱性、インストールスクリプト追加、公開直後のパッケージなどをポリシーで制限。Dependabot の malware alert で検知し、到達可能性を CVSS・EPSS・本番利用状況と合わせて優先度を決める。スライドでは到達可能性分析の対象として JavaScript／TypeScript を挙げた。
- **デモ**：105件の依存関係アラートのうち到達可能な13件を絞り込み、バージョン更新で破壊的変更が生じた場合にはエージェントに修正 PR を依頼。VS Code の `/security-review` は接続の問題でその場で起動せず、事前実行の結果を使って XSS・SSRF・SQL インジェクションの指摘を説明した。
- **秘密情報**：push protection で対応する秘密情報を push 前に止め、独自の正規表現や AI 検出も利用。デモでは秘密情報を security campaign にまとめ、期限と担当を設定して是正を追跡する。
- **提供状態と注意**：登壇者は紹介内容を github.com で GA または public preview と説明したが、個々の機能の区分は明示していない。Dependabot malware alerts と到達可能性分析は無料と説明。到達可能性は単独でリスクを決定するものではない。
