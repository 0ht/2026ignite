## 概要

Azure AI Landing Zones の設計・参照アーキテクチャと実装例を通じ、Foundry エージェントを PoC から運用へ移す。

## 内容の要点

- **設計**：既存の Azure platform landing zone のポリシーを AI ワークロードに継承し、Foundry の構成、エージェントデータ、ネットワーク、実行環境、grounding、AI gateway の6点を決める。チーム間の隔離が必要なら Foundry アカウントを分離し、共有可能なら複数プロジェクトを置く。
- **構成例**：Agent Landing Zone をワークロードの spoke、AI Gateway Landing Zone を共有モデル・利用制限の hub とする。API Management で認証、トークン制限、安全性、ルーティング、利用量を扱い、private endpoint、managed identity、hub firewall を組み合わせる。
- **デモ**：請求書調査アプリ Waypoint の Bicep パラメーターで private network、共有ゲートウェイ、Foundry IQ を設定。`azd provision`／`azd deploy` 後、契約の根拠を示して請求書をエスカレーションし、Application Insights と Foundry のトレース・評価結果を見る。評価は3テストケースの例であり、普遍的な精度保証ではない。
- **制約と当時の状態**：標準のエージェントデータは自社サブスクリプションに置けるが、hosted agent の各セッションのホーム領域は Microsoft 管理。プロジェクトの保存先は後から変更できない。スライドでは Fabric IQ／Work IQ はネットワーク分離プロジェクト非対応、publish contract はプレビュー。新しい AI gateway リソースの landing zone 対応は計画中で、安全性ポリシー等のプレビュー機能を待つと説明した。
