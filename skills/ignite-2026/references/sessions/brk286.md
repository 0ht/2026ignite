## 概要

GitHub Actions のサプライチェーン攻撃を5段階でたどり、checkout、キャッシュ、ポリシー、依存固定、ネットワーク制御を組み合わせる。

## 内容の要点

- **信頼境界**：`pull_request_target` の信頼された実行環境で外部 PR のコードを実行すると、共有キャッシュを汚染し、権限の高い release workflow に波及し得る。新しい checkout の既定保護は危険な fork head 等を拒否するが、あらゆる未信頼コードの取得・実行を防ぐ保証ではない。未信頼実行のキャッシュは読み取り専用、重要な release job は `cache-mode: none` も選べる。
- **デモ**：可変タグの差し替えにより、直接依存を SHA 固定しても composite action の間接依存が変化する例を示す。Actions lock file は直接・間接依存を固定し、実行時にも検証する。別のデモでは firewall の許可リスト外への送信をブロックしたが、固定済み action が外部スクリプトを取得するリスクは残る。
- **エージェントとネットワーク**：Agentic Workflows は自然言語から Actions YAML を生成し、読み取り専用と safe outputs を基本とする。Azure VNet に接続した hosted runner を Copilot cloud agent に割り当て、既存のネットワーク制御を適用する。
- **発表当時の状態**：スライドでは lock files、cache mode、Agentic Workflows、Azure private networking などは GA。スライドでは `pull_request_target` の block enforcement は2026年12月2日予定。Actions Firewall は technical preview、keyless GitHub App tokens は社内提供段階で2027年1〜3月のプレビュー予定。lock file の reusable workflow／Docker action 対応は今後の予定。保護機能の有効化自体は追加料金なしだが、計算・AI 利用料金は別途発生する。
