## 概要

Work IQ とコネクターを使い、Microsoft 365 の文脈やアクセス権に基づいた個別化エージェントを複数の開発環境で構築します。

## セッションの内容

開発者が Work IQ を MCP、REST、エージェント間連携から利用し、メールや会議、業務アプリに分散した情報をエージェントにつなぐ方法を紹介します。架空の顧客ポータル開発を例に、コードと Jira に記録されていない会議上の決定を見つけ、修正につなげました。

### リリース判断からコード修正まで

Copilot Studio で作成したリリース準備エージェントは、GitHub、Jira、Teams の情報を使い、カナダ向けポータルの英仏二言語対応が未完了であることを検出します。管理者と開発者では見える情報が異なり、利用者の権限に応じて結果が変わる例も示しました。

GitHub Actions のワークフローでは、変更を分析した後、Work IQ に接続した Teams エージェントがマーケティング担当者向けの影響と次の作業を通知します。VS Code と Claude Code に MCP を追加し、業務上の決定を参照してコードを修正するデモも紹介しました。

### 開発者向けインターフェースと管理

Work IQ は少数の共通ツールと拡張可能なパスを組み合わせて、情報の取得や操作を行う設計です。`retrieve` の grounding では、利用者の権限に応じて絞り込まれた引用元付きの根拠を返し、回答の生成は呼び出し側のモデルが担います。

イベントを検出してエージェントを起動する `listen`、メモリや文書操作なども紹介されました。`listen` は発表時に 12 月 4 日からのパブリックプレビュー予定と説明されています。テナントとエージェント単位のポリシー、実行履歴、利用額の制限を Agent 365 で管理する考え方も取り上げています。
