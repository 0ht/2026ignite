## 概要

Web IQ API で最新情報を取得し、引用付き回答を生成する流れと、遅延・トークン・トレースによる改善を説明します。

## セッションの内容

Web IQ の API を使って公開情報を取得し、引用付き回答につなげる手順と、Toyota の開発中の車載 AI エージェントにおける技術検証を紹介します。

### API と情報源の制御

REST の Web 検索では、検索語、結果数、出力形式、結果ごとの文字数などを指定します。`passage` 形式はページ全体ではなく関連する部分を返し、応答にはタイトル、URL、コンテンツ、公開元の更新時刻やクロール時刻などが含まれます。利用者やエージェントが根拠と鮮度を確認するための情報です。

Scopes で許可・除外するドメインやパスを設定でき、Auto は複数の検索先の選択を支援します。場所と天気は発表時点で一般提供、Commerce はプライベートプレビューとして紹介されました。天気を利用した現場作業の例では、安全手順や現地の状況も併せて確認する必要があると説明しています。

### Toyota の車載技術検証

Toyota は製品化前の検証として、走行方向と車両情報を踏まえて橋の通行料を案内する例を示しました。充電設備の例では Foundry IQ で車両の取扱説明書を参照し、Web IQ の周辺施設情報と組み合わせます。昼食先の例では運転者の好みも利用します。

車載エージェントは開発中で、Foundry のトレース、評価、改善を繰り返す構想です。国、言語、車両環境ごとの安全性やプライバシー要件を踏まえ、実車で検証を続けると説明されました。
