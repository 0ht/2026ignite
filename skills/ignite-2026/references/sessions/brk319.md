## 概要

Codename MDASH が複数の専門エージェントを使ってコードの脆弱性を発見・検証・優先順位付けする流れを説明します。

## セッションの内容

Codename MDASH は、複数の専門エージェントとモデルを組み合わせ、ソースコードの複雑な脆弱性を探索する仕組みです。発表時点ではプライベートプレビューとして紹介されました。

### 検出から修復まで

コードと攻撃対象を把握したうえで候補を検出し、別のエージェントが候補の成立を支持・反証して、重複する結果を整理します。認可の欠落やメモリ処理など、複数箇所にまたがる問題を例に挙げました。

架空の配送アプリのデモでは、認証やアクセス制御の欠陥を調査し、Defender の結果画面で重大度、根拠、検証内容を確認します。修復案をプルリクエストとして開発者に渡し、コードをレビューして再テストする流れを示しました。出力はポータルに加え、SARIF や HTML としても利用できます。

### 運用のポイント

登壇者は、既存の静的解析やシークレット検出を継続し、MDASH をより深い探索に併用するよう勧めています。重要かつ外部に公開されたアプリから始め、担当者、修復能力、スキャン時間と推論費用を確認します。検出結果には環境や既存の制御に関する情報を加えて優先順位を付け、修正をテストしてから反映することが重要です。

Foundry のモデル推論を利用し、利用量に応じた費用が発生します。Perception の Web アプリ検証との連携と、今後の GitHub Advanced Security での深いスキャンについても紹介されました。
