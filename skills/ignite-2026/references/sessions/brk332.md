# BRK332: Identity Knows What Your SOC Doesn’t: Stop Threats Faster Together

## 概要

Entra の ID コンテキストを Defender の SOC 調査に取り込み、ID 管理者とセキュリティ担当者の連携を改善します。

## セッションの内容

ID の作成・管理、条件付きアクセスによる制御、脅威の検出と対応をつなぎ、ID 管理者と SOC が同じコンテキストで判断できるようにする考え方を紹介します。

### ハイブリッド ID の攻撃を追う

デモはオンプレミスのユーザーから権限の高いアカウント、クラウドへと攻撃が進むシナリオです。Defender で複数のアラートを一つのケースとして関連付け、同じ人物の複数アカウントとリスクを確認しました。攻撃の後続段階を見せるため、このデモでは自動的にユーザーを無効化する部分を止めています。Entra では、ユーザーが本人確認を行いリスクを解消する例を示しました。

### エージェントのリスクをアクセス判断へ反映する

Agent 365 の一覧で未承認のエージェントを探し、実行時の検出、露出、影響範囲からなる Dynamic agent risk を確認します。デモでは Defender と Purview の検出後にリスクが上がり、高リスクのエージェントを対象とする Conditional Access ルールがアクセスを停止しました。

続いて、デバイスコードを使ったフィッシングでエージェントのセッションが悪用される例と、Defender による自動対応を紹介しました。Perception のプレイブックは、既存ポリシーの対象外になったユーザーを調べて対策を提案します。デモでは管理者が承認し、レポート専用モードで影響を確認してから展開します。
