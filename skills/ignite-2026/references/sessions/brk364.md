## 概要

Azure Databricks と Foundry、Fabric、Copilot の連携を通じたデータ・AI 基盤の構築方法を紹介します。

## セッションの内容

### データと管理の基盤

Azure Databricks を Microsoft の請求・サポートと連携するサービスとして紹介し、Lakeflow、Lakehouse、Lakebase に加え、Unity Catalog でデータやモデル、エージェントを管理する構成を説明しました。Unity Gateway はモデルの利用、利用者やチーム別の予算、アクセス、トレースを管理する入り口です。

サーバーレスからプライベートネットワークへの接続を簡素化する Private Network Gateway は、発表時点でパブリックプレビューです。

### Fabric と相互にデータを利用

Databricks の Unity Catalog を Fabric にミラーすると、カタログのメタデータを同期し、データはショートカットで参照します。逆方向では OneLake Catalog Federation により Databricks から OneLake のデータをコピーせずクエリします。それぞれ利用側の計算資源で処理されます。

Databricks の管理テーブルを OneLake に保存する機能はパブリックプレビューとして紹介されました。Unity Catalog と OneLake のセキュリティポリシーの連携は対象や設定を確認する必要があります。スライドと発言には、ストリーミングテーブルなどの対象範囲に食い違いがあるため、利用前に最新の製品情報を確認してください。

### AI ツールとの連携

Teams や Copilot から Genie のデータ分析を利用する構成、Agent 365 に Databricks の AI 資産を登録・同期して権限のある管理者が停止できる例を紹介しました。Foundry のモデルを Unity Gateway 経由で利用し、GitHub Copilot などの利用に予算やポリシーを適用する構想も説明しています。スライドでは Genie の Teams・Copilot 連携はベータと記載されています。
