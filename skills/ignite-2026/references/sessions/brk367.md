## 概要

Cosmos DB を用い、エージェントの状態・記憶とベクトル検索やハイブリッド検索を組み合わせる設計を説明します。

## セッションの内容

### エージェントが操作するデータ

Cosmos DB Agent Kit は、データモデルやパーティションキーなどの推奨をコーディングエージェントに提供します。管理型 MCP サーバーは Entra ID 認証でデータベースに接続し、発表時点ではプレビューとして読み取り専用のアクセスを紹介しました。エージェントにも通常のアプリと同じ ID、認証、ロール・権限、診断ログを適用し、プロンプトだけに安全性を委ねない考え方を示しています。

デモでは、MCP 経由で注文データを調査してコードの不具合を発見し、解決内容のみを Cosmos DB に保存しました。別の開発者は新しい会話からベクトル検索と絞り込みで過去の解決例を見つけ、現在のデータとコードで再検証しました。会話全文を長期記憶に保存する設計ではありません。

### 会話、記憶、業務データ

セッション中の会話履歴や作業状態は一時的なコンテキスト、利用者の継続的な好みなどは将来の対話に使うメモリ、注文や顧客情報は業務データとして区別します。Agent Memory Toolkit は記憶の抽出、保存、検索、整理・削除を支援し、複数エージェントが共通のメモリと状態を利用しながら、各自の ID と権限を保つ構成を紹介しました。スライドでは Python SDK がプレビューと記載されています。

### 質問に応じた検索

既知のキーや構造化条件には通常クエリ、用語が重要なら全文検索、言い換えや意味の類似性にはベクトル検索、両方必要ならハイブリッド検索を使い分けます。検索で候補を集めた後、セマンティック・リランカーで関連度順に並べる二段階の流れを説明しました。セマンティック・リランカーは一般提供、マルチモーダルの Microsoft Embedding One はパブリックプレビューとして発表されています。

### Willis Towers Watson の事例

従業員の福利厚生支援アシスタント Violet は、企業ごとに異なる給付制度や資格条件に沿った回答を行うため、コンテンツ、テナントやアクセスのメタデータ、埋め込みを同じ Cosmos DB レコードに保存しています。変更フィードから埋め込み処理を非同期で更新し、実行時にはテナント・資格条件で絞ったハイブリッド検索と順位統合を行い、会話に必要な情報をモデルへ渡します。

WTW は索引・全文検索ポリシーを早期に決めること、実際のハイブリッド検索全体で RU 消費を測ること、同時実行と非同期埋め込みを含む負荷試験を行うこと、遅延・再試行・429 応答を監視することを運用上の教訓として挙げました。
