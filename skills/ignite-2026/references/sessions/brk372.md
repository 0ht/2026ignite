## 概要

Fabric の SQL database、OneLake へのミラーリング、ベクトルと MCP を組み合わせ、エージェントと分析をつなげます。

## セッションの内容

### Fabric 内の SQL 運用データ

SQL database in Fabric は Microsoft SQL エンジンを使う SaaS 型データベースです。作成時は名前を指定し、サーバーレスのスケーリングや一時停止、ゾーン冗長性などを既定で管理します。最大 vCore の指定や ALTER DATABASE SET など、要望を受けて管理者向けの制御も加えたと説明しました。

作成したデータベースは Fabric の OneLake にほぼリアルタイムでミラーされ、SQL 分析エンドポイントやショートカットを通じて Fabric の分析機能に接続できます。既定で全テーブルをミラーする構成に加え、対象テーブルを選択する方法も紹介しました。既存の Azure SQL や SQL Server もミラーリングし、運用データを Fabric に集約できます。

### AI エージェントと分析

Caldova の社員食堂のデモでは、Fabric Apps で作った食品廃棄記録アプリの裏側に SQL データベースを用意しました。SQL データと既存 Azure SQL のミラーを OneLake のショートカットから Lakehouse に組み合わせ、Notebook やデータエージェントで廃棄傾向を分析します。

ワークスペースの GitHub / Azure DevOps 連携によるデータベースコードのソース管理や、SQL プロジェクトを使った開発・デプロイにも触れました。Database Hub、Copilot、データベースエージェントによる運用・診断も、SQL 全体で進める機能として紹介しています。

### Uniwise の財務計画アプリ

Uniwise は Targetty という財務計画・レポーティング製品を Fabric 上で構築し、約 3,000 人が利用している事例を紹介しました。従来は複数の Azure サービスを組み合わせていましたが、アプリ、SQL データベース、分析、レポートを Fabric の容量にまとめています。

SQL データベースは計画値、マスターデータ、監査記録を保持し、ストアドプロシージャで業務ルールや書き込み制御を実施します。レポートに必要なテーブルだけを OneLake にミラーし、アプリとデータを別ワークスペースに分けてアクセスを制御します。サーバーレスの起動遅延を考慮した再試行、ワークロード計測、vCore 上限の設定も運用上のポイントとして挙げました。

Targetty のエージェントは計画や予測を提案しますが、保存前に利用者が内容を確認・承認します。Uniwise は開発でも複数のエージェントによる実装・レビュー、CI、テストを活用し、最終承認とマージは人が行う流れを紹介しました。
