# BRK378: Host apps from anywhere with the new Copilot Managed Runtime

Copilot Managed Runtime を使い、さまざまな環境で作成したアプリを企業向けの管理・セキュリティ基盤へ取り込みます。

確認日 2026-11-24

<!-- Manually curated session; catalog refresh keeps this article. -->

## 概要

Copilot Managed Runtime を使い、さまざまな環境で作成したアプリを企業向けの管理・セキュリティ基盤へ取り込みます。

## セッションの内容

### 作る場所を選び、同じ基盤でホスト・管理する

Copilot Managed Runtime（CMR）の主題は、Cowork、Copilot Studio、開発者向け CLI、Lovable など好みの環境でアプリを作り、Microsoft 側の共通基盤でホスト・管理することです。登壇者は、各アプリに Entra による認証、Git バックのソース管理、Microsoft Admin Center での可視化を適用し、利用者の作成環境を限定せずに企業の統制を保つ仕組みとして説明しました。

管理者が設定した環境、接続先、共有範囲のルールを、アプリ作成中のエージェントにも伝えて不適切な構成を避ける方針を紹介。1,500超のコネクタに対応すると説明する一方、既定で使えるのは「green zone」と呼ぶ限定セットで、追加の接続先や共有設定は管理者が許可します。エージェントをアプリ内に組み込むことで、データ表示にとどまらず分析や操作も行う構成を示しました。

### Cowork と Copilot Studio でのアプリ作成

Cowork のデモでは、既存の資料から Atlas プロジェクトの Q4 ロードマップを一覧・編集できるアプリにし、チームと共有しました。Figma の画面デザインを参照してアプリを作る例では、完成した画面を SharePoint リストにつなぎ、見た目の試作を組織内で共有・管理できるアプリにする流れを実演しました。

Copilot Studio では、Dataverse の現場点検データを使う「Gauge」アプリを紹介。合格率、再発する指摘、失敗箇所のヒートマップを表示し、アプリ内の Risk Advisor エージェントに「North Yard で期限超過している是正項目」を質問すると、デモデータから2件を返しました。別途、期間とデータに応じた要約も組み込みましたが、登壇者はこれを自律的に動くエージェントではなく、単純な LLM プロンプトと区別して説明しました。

### Lovable・開発者 CLI と管理者の統制

Lovable のデモは、新入社員ごとのオンボーディングアプリを作成し、Entra ID で利用者を識別、Excel の一覧をデータ源としてタスクを表示・完了にするものです。Lovable の登壇者は、アプリのフロントエンドを CMR に公開し、Microsoft 365 テナント内でホスト・管理する構成を紹介しました。

開発者向けの例では、Copilot Studio で作った Gauge アプリを Git リポジトリから VS Code に取り込み、Copilot で地図表示を追加してローカル開発サーバーで確認する手順を実演しました。Microsoft Admin Center では、アプリ一覧や利用状況、接続先を見て、必要に応じてアプリをブロック・隔離する操作のほか、環境グループごとのコネクタ／操作、共有方法、Content Security Policy、支出上限の設定を示しました。

### セッション時点の提供状況

登壇者は録画時点で、CMR、Cowork のアプリ作成機能、Copilot Studio のアプリ、Intelligent Apps を一般提供（GA）として紹介しました。一方、エージェントやワークフローを CLI から作る機能はプレビューと説明しています。Copilot Code からアプリを作る方法は別セッションで扱うとのことで、このセッションでは実演していません。これらは2026年11月の発表時点の説明であり、現在の提供状況を独立に確認したものではありません。
