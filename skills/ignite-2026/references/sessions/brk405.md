## 概要

Windows の基盤、サインイン、暗号化、端末保護と AI 時代のセキュリティ対策を紹介します。

## セッションの内容

登壇者は、AI によって脆弱性の発見・悪用・修正のサイクルが速まる一方、量子計算への備えも今から始める必要があると説明し、Windows セキュリティを三つの柱で整理しました。すなわち「安全に開始し、保ち続ける」「管理外の端末も含めて仕事を守る」「AI エージェントの可能性を安全に広げる」です。量子耐性暗号については、鍵交換で ML-KEM（ハイブリッドまたは純粋方式）を展開し、認証では証明書資産と依存関係を把握して ML-DSA 証明書への移行を計画する、という段階的な備えを促しました。

基盤側では、TPM 2.0、Secure Boot、VBS などのハードウェア保護を対象端末へ広げ、複数の重要な保護状態を一つに示す Windows baseline protection を紹介。標準ユーザーを基本とし、必要な操作だけ Windows Hello で一時昇格する Administrator protection、サードパーティ製セキュリティ部品をカーネル外へ移す Windows endpoint security platform、ドライバー品質向上の取り組みも説明されました。NTLM 依存の縮小には、ドメインコントローラーへ直接到達できない場合の IAKerb とローカルアカウント向け Local KDC など、Kerberos への移行を助ける機能を挙げています。更新面では Autopatch と Hotpatch により、段階展開の可視性を高め、再起動待ちによる保護遅延を減らす考え方が示されました。

サインインやデータ保護では、顔認証と PIN 入力を並行させる Windows Hello の改善、ハイブリッド参加端末への Web サインイン、個別のセキュリティキー管理、標準ユーザーが設定できる BitLocker TPM+PIN、紛失端末のリモートロックを紹介。宣言型管理は、証明書・Wi-Fi・VPN などの意図した状態を端末側で維持し、接続が途切れた場合もポリシーを保つ仕組みとして説明されました。

管理外端末については、用途に応じて Edge for Business、Windows 365、Azure Virtual Desktop を使い分ける構成を示し、Windows App の Intune アプリ保護ポリシーや、Microsoft Entra の認証コンテキストに応じてクリップボード・ドライブ・プリンター・USB の転送を制御する方法を紹介。リモートセッションの入力保護・画面保護にも触れています。最後に、エージェントごとの ID、MXC による実行境界、Intune と Agent 365 による管理を組み合わせ、エージェントの行為を識別し、アクセス可能なデータや操作を統制する方向性をまとめました。
