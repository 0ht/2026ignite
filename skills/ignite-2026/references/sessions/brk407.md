# BRK407: What's new in Windows Management

確認日 2026-11-24

## 概要

Windows Autopatch の更新管理、状態の可視化、アプリ管理、端末からサーバーまでの管理を紹介します。

## セッションの内容

登壇者は、AI による脆弱性発見で修正・展開を急ぐ必要が高まるなか、更新を速めながら品質と業務継続性を保つための Autopatch の改善を、制御、健全性の可視化、アプリとエージェントへの拡張、管理の基礎という観点で説明しました。Johnson & Johnson の事例では、約20万台の Windows 端末を対象に、品質更新からドライバー、BIOS、ファームウェアへ Autopatch の対象を広げ、運用の手作業を減らした一方、セキュリティ部門が求める更新速度にはまだ改善余地があると共有しました。

OS 更新では、短い延期期間を促す既定値、オプション更新・帯域外更新・Quick Machine Recovery の個別承認、GA となったメンテナンスウィンドウを紹介。新機能の適用予定を事前に把握する表示もプレビューとして説明されました。Device Health の初期機能は OS Reliability で、停止エラーや影響端末の傾向を確認し、特定更新の前後で信頼性がどう変化したかを比較するものです。端末上の Copilot による Bluetooth などの診断・修復も紹介されましたが、登壇中のライブデモは一度うまく動作せず、後の説明用デモで補われています。

アプリの更新では、Enterprise App Management（EAM）に Microsoft Store の信頼済みカタログを使った自動更新を追加し、更新リング、延期、期限を OS 更新に近い形で設定するプレビューを示しました。組織が個別に管理するアプリは自動更新対象から外し、それ以外をまとめて更新できる設計です。また、MXC の Intune ポリシーで、対応エージェントのファイルアクセスやネットワーク利用を制限し、未承認の場所へのアクセスを拒否するデモがありました。

管理の基礎として説明された宣言型管理は、管理者が望ましい状態を指定し、端末がその状態を継続的に維持するモデルです。Wi-Fi、VPN、有線接続などから始め、従来の OMA-DM よりポリシー同期を速く・確実にする狙いが示されました。Autopatch による Windows Server 2008 管理も発表されました。これらの一部はプレビューや段階的な展開として説明されているため、個々の提供状況は最新の公式情報で確認が必要です。
