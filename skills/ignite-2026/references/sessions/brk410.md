## 概要

GitHub Copilot とエージェントを使い、Java・.NET アプリの更新、依存関係の修正、コンテナー化とデータベース移行を進めます。

## セッションの内容

- **ポートフォリオの一括評価**：架空の Caldova Insurance を例に、Modernize CLI にローカルまたは GitHub のリポジトリ一覧を渡し、Java と .NET の12アプリをまとめて評価した。デモでは Java 25 と .NET 10 を目標に、旧バージョン、クラウド対応、セキュリティを調査。集約レポートから個別アプリの構成、課題、移行ウェーブ、概算コストを確認する。概算は小売価格ベースであり、契約価格そのものではない。
- **アプリとデータベースを一緒に変更**：CLI のデータベース統合はプレビューとして紹介された。Oracle から PostgreSQL への移行では、まず VS Code の PostgreSQL 拡張でスキーマとデータの移行を進め、生成した DDL を CLI に渡す。デモでは Java と Spring Boot の変更をいったん抑え、データアクセス側の変更計画を人がレビューして実行し、移行後の PostgreSQL に保険請求が記録される流れを説明した。
- **組織の標準を反映**：一般提供の rulebook は、対象フレームワーク、禁止パターン、命名規約などを Markdown で記述し、CLI で charter・policies・targets に整理して共有リポジトリへ公開する。各リポジトリの設定から参照し、計画と実行後の evidence を確認する。独自の命名規則やスクリプトを含む custom skills も使い、Azure Container Apps への移行計画に組み込む例を示した。
- **モダナイズ後の業務体験**：デモでは既存の保険アプリをコンテナー化して Azure に移し、さらにモノリスを API／サービスへ分割。Foundry の受付エージェントが自然言語や画像から自動車・住宅の請求に必要な情報を整理し、不足事項を質問して担当者の確認につなげる。これは完成済みのデモ構成であり、移行ツールだけで自動的に実現するという意味ではない。
- **着手の90日案**：最初の30日で成果指標と現状を定めランディングゾーンを整え、60日までに価値の高い少数のワークロードで実行と測定を行い、90日までにガバナンス、次のウェーブ、実績に基づく投資根拠を整える。移行計画のレビューとテストを人が担うことを強調した。
