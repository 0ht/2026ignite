## セッションの内容

このセッションでは、ソブリン環境を単一製品としてではなく、データ所在地、アクセス制御、運用主体、AIの実行場所、接続断への備えをワークロードごとに組み合わせる考え方を示します。Microsoftの選択肢として、統制を加えたパブリッククラウド、Azure Local上のプライベートクラウド、地域のパートナーが独立運用するクラウドを対比し、強い分離を選ぶほど冗長性や運用責任とのトレードオフが増える点にも触れています。

Azure Localを基盤に、仮想マシンやAKSから、Foundry Local、Microsoft 365 Local、GitHub Enterprise Local、SQL Server、Blob Storage、DocumentDBまでを段階的に追加する構想を説明。発表時点では、Foundry LocalとGitHub Enterprise Local、SQL Server on Azure Localが一般提供、Blob StorageとDocumentDB on Azure Localがプレビューとして紹介されました。Azure Localインスタンスの「re-home」は、VMやAKS、アプリケーション、データを移行せずに管理プレーンをAzure側からローカル側へ移すプレビュー機能です。マルチテナンシーもプレビューとして、共有・専有インフラを組み合わせ、複数拠点の容量をprivate zoneにまとめ、capacity poolやcapacity sliceを通じてテナントや部門に上限付きのセルフサービスを提供する設計が示されました。

保護機能では、Confidential VMの一般提供と、GPU上の機密データやモデルも保護するConfidential GPUの今後の対応を紹介しました。大規模推論向けにはAzure Local、Foundry Local、NVIDIA HGX B300、OEM各社の検証済み構成を組み合わせる計画を示し、当時の目標時期は2027年前半と説明されています。Azure上のアプリを移す場合は、Sovereign Landing ZoneのポリシーでAzure固有サービスへの依存を調べ、適応・検証したうえで計画的に切り替える手順を提示しました。

導入例として、Golden Gate Bridge Highway and Transportation District（GGBHTD）の担当者が登壇。約3年の移行過程で約150台のVMをAzure Localへ移し、VMwareのライセンス変更も移行理由の一つだったと説明しました。ローカル実行が必要な交通アプリをAzure Localで運用しつつ、Azure ArcとAzure Update Managerで管理・パッチ適用を行い、クラスターの更新時にも利用者に停止を感じさせずに済んだと報告しています。ローカルバックアップのAzureへの複製やAzure Site Recoveryの検証も紹介されました。これは登壇者による顧客事例であり、全環境に同じ結果を保証するものではありません。
